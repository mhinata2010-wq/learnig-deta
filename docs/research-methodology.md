# 調査方法と限界（2026-11-04）

## 目的
建築施工管理SaaSの公開フィードバックから課題を抽出し、Building Scheduleの実装と比較する。目標は**検証可能なユニークレビュー1,000件**の収集。

## 今回の到達点
- 9製品を対象に公開レビュー掲載ページから**課題シグナル91件**を要約・構造化した。
- **個別レビューの取得数として91件とは主張しない**。1つのレビューに複数の課題が含まれる可能性、別レビューから同じ課題を抽出する可能性がある。
- 原典URLは現状、ほとんどが**レビュー一覧ページ**でありレビュー個票の特定・投稿日時・引用の確認は未完了。
- 課題の文言は原文引用ではなく日本語での要約。評価の正確さはレビュー個票を再取得して追検証する必要がある。
- 1,000件は**未達**。件数を水増ししたり、AI生成の擬似レビューを混入させない。
- 状態判定は2026-11-04時点のbuilding-schedule `main` のコードと設計文書に基づく暫定監査。E2E・実機検証による課題解決効果を示すものではない。

## 収集の次段階
1. レビューサイトごとに利用規約・引用方針・公開可否を確認。
2. 取得するごとに `review_id` / `review_deep_link` / `review_published_at` / `captured_at` / `product` を記録。
3. `platform + review_id` で重複排除。IDが取れない場合は明示的に「未確認」に分類。
4. 1レビューから複数課題を抽出した場合、`review_id` に対する1対多の関連を維持する。
5. ユーザー属性、評価、投稿年月で層化し、極端な否定的評価だけが偏らないようにする。
6. プロダクト実装の評価は `コード上の機能有無 → ブラウザE2E → 現場ユーザーテスト → 課題改善KPI` の4段階で記録。

## 定義
- `未実装`：該当する機能が見つからない。
- `一部対応`：周辺機能はあるが業務の終端までは解決できない。
- `実装あり・E2E未検証`：コードに該当機能があるが実機で未確認。
- `未検証`：性能・利用環境に依存し実測が必要。
- `スコープ外`：現在の工程管理MVPの機能範囲外。

## 留意点
企業製品への不満を記した要約は、その製品が常にその問題を有するとの断定ではありません。レビュー掲載ページと原投稿を分けて追跡してください。
