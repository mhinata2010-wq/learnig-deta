# 実装・検証ロードマップ

| 優先度 | 施策 | 検証方法 | 合格条件の提案 |
| --- | --- | --- | --- |
| P0 | Gantt E2E（作成・移動・削除・後続一括シフト） | PC+スマホ実機、依存あり/なし/完了済みパターン | 重要操作20シナリオで重大バグ0件 |
| P0 | 共有・認証・権限・同期 | 現場監督と協力業者の2アカウントで更新 | 同じ工程の最新版が反映され、権限外編集ができない |
| P0 | 工程変更通知・受領確認 | 変更を3名に配信、閲覧・確認証跡を照合 | 誰がいつ確認したか監査可能 |
| P0 | Excel/CSVインポートとA4/A3印刷 | 現場で使用中の工程表5種で検証 | 読み込み失敗0、印刷で重要文字・日付の欠落0 |
| P1 | 写真・日報と工程の紐づけ | 現場監督5名ヒアリング + PoC | 更新した工程から関連情報に2操作以内で到達 |
| P1 | 複数現場ダッシュボード | 3現場のタスク切り替え | 誤った現場への登録0 |

## MVPの境界
**まず「工程表の編集→変更通知→受領確認」までを一貫して解決**。写真、原価、BIM、勤怠を短期的に全搭載する判断はしない。

## KPI（提案・未検証）
- 工程を1件追加する時間（中央値、従来Excelとの比較）
- 工程変更から受領確認までの所要時間
- 変更を認識できていない協力会社数
- 7日間の現場アクティブ率と初期設定完了率
- CSV/Excel移行で発生した二重入力の件数

## 今後の検証
1. 現場監督・職人・協力会社の各役割を含む5人にインタビュー。
2. 同じ工程変更タスクをExcel、既存SaaS、Building Scheduleで比較。
3. 機能実装の前に「通知だけで十分か」「確認ボタンが必要か」をテスト。
4. 調査データの原典レビュー個票への追跡を進める。
